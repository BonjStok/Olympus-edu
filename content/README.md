# Контент «Олимпуса»: формат и правила

Здесь лежит исходный учебный контент и календарь олимпиад. При сборке
(`pnpm compile-content`, он же первый шаг `pnpm build`, `pnpm dev` и Docker-сборки) все файлы
проверяются и собираются в `lib/seed.json`, который загружается в PostgreSQL. Полная схема полей и
правил – [docs/DATA.md](../docs/DATA.md#4-схема-контента); редактирование через админ-панель –
[docs/TEACHER-GUIDE.md](../docs/TEACHER-GUIDE.md).

## 1. Где что лежит

```text
content/
  topics/      math-4.json … info-6.json   – 72 темы (12 на класс и предмет)
  lessons/     math-4.json … info-6.json   – 360 уроков (по 5 на тему)
  tasks/       math-4.json … info-6.json   – 360 заданий (по 5 на тему)
  mock-tests/  initial.json, max-2026.json – 12 пробников
  olympiads/   2026-27.json                – 501 олимпиада сезона 2026/27
  <тип>/imports/                           – необязательные дополнения (сейчас пустые)
```

- Файл – JSON-массив записей (или один объект). Поле `kind` в файлах не пишется: его задаёт папка.
- Файлы читаются по алфавиту, сначала верхний уровень папки, потом `imports/`. Запись с тем же `id`
  в более позднем файле **заменяет** предыдущую; тот же `id` в папке другого типа – ошибка.
- `id` – латиница, цифры, `_` и `-`, до 100 символов. Он постоянный: на него ссылаются прогресс
  детей, другие записи, бот и `test-data.json`. Не переименовывайте опубликованные записи.

Принятые имена:

| Тип | Шаблон `id` | Пример |
|---|---|---|
| тема | `<предмет>-<класс>-<NN>` | `math-4-01` |
| урок | `<тема>-lesson-<n>` | `math-4-01-lesson-1` |
| задание | `<тема>-task-<n>` | `math-4-01-task-1` |
| пробник | `mock-<класс>-<предмет>`, `max-2026-<предмет>-<класс>` | `mock-4-math` |
| олимпиада | `<название-латиницей>-<сезон>` | `moscow-math-festival-2027` |

## 2. Форматы с примерами

### Тема

```json
{ "id": "math-4-13", "title": "Числовые ребусы", "grade": 4, "subject": "math", "order": 13,
  "description": "Восстанавливаем стёртые цифры в примерах и учимся перебирать варианты с умом" }
```

`subject`: `math` или `info`; `grade`: 4, 5 или 6.

### Урок

```json
{ "id": "math-4-13-lesson-1", "title": "Что такое ребус", "topicId": "math-4-13", "order": 1,
  "blocks": [
    { "type": "text", "value": "В числовом ребусе одинаковые буквы обозначают одинаковые цифры…" },
    { "type": "example", "value": "АБ + АБ = 88. Значит, АБ = 44: …" },
    { "type": "list", "value": "Первый пункт\nВторой пункт" },
    { "type": "table", "value": "a | b | a+b\n1 | 2 | 3" },
    { "type": "formula", "value": "\\frac{a}{b} + \\frac{c}{d}" },
    { "type": "code", "value": "print(2 + 2)" },
    { "type": "image", "value": "https://example.ru/picture.png", "caption": "Подпись" }
  ] }
```

Типы блоков: `text`, `example`, `list` (пункты через `\n`), `table` (строки через `\n`, ячейки через
`|`), `formula` (KaTeX), `code`, `image`, `video`, `link`. Для `image`, `video`, `link` – только
`https://…` или загруженный файл `/api/media/<id>`. Класс и предмет урока берутся из темы.

### Задание

```json
{ "id": "math-4-13-task-1", "title": "Две одинаковые буквы", "topicId": "math-4-13",
  "type": "number", "order": 1, "points": 1,
  "prompt": "АА + А = 36. Какая цифра спрятана под буквой А?",
  "answer": "3",
  "hint": "АА – это двузначное число из двух одинаковых цифр",
  "solution": "АА + А = 11·А + А = 12·А = 36, значит А = 3. Проверка: 33 + 3 = 36. Ответ: 3." }
```

- `type: "number"` – числовой ответ `answer` (целое или десятичное, `0,5` = `0.5`);
- `type: "proof"` – рассуждение, ребёнок сверяет его с разбором сам (ответ не нужен);
- `type: "code"` – программа: `tests` (1–20 пар `input`/`output`, скрытые) и `example` –
  публичный пример, **равный первому тесту**; `solution` – эталонная программа на Python:

```json
{ "id": "info-4-13-task-4", "title": "Удвоение", "topicId": "info-4-13", "type": "code",
  "order": 4, "points": 2,
  "prompt": "Дано целое число n. Выведи 2·n.\n\nВходные данные: …\n\nВыходные данные: …",
  "hint": "Прочитай число через int(input())",
  "solution": "n = int(input())\nprint(2 * n)",
  "tests": [ { "input": "2\n", "output": "4" }, { "input": "0\n", "output": "0" },
             { "input": "-7\n", "output": "-14" } ],
  "example": { "input": "2\n", "output": "4" } }
```

### Пробник

```json
{ "id": "mock-4-math", "title": "Пробный тур по математике · 4 класс", "grade": 4,
  "subject": "math", "olympiad": "Пробный тур Олимпуса", "minutes": 60, "randomize": false,
  "taskIds": ["math-4-01-task-2", "math-4-03-task-2"] }
```

Задания – существующие, того же класса и предмета, без повторов. Случайная выборка:
`"randomize": true` и `"taskCount": 12` (не больше числа `taskIds`).

### Олимпиада

```json
{ "id": "example-olympiad-2026-27", "title": "Название олимпиады", "subject": "math",
  "grades": [4, 5, 6], "format": "online", "region": "", "stage": "Отборочный тур",
  "registrationType": "link", "url": "https://организатор.рф/регистрация",
  "registrationStart": "2026-10-01", "deadline": "2026-10-20", "date": "2026-10-25",
  "dateEnd": "2026-10-27", "price": 0, "image": "", "featured": false,
  "description": "Кратко: кто проводит, как проходит, что важно знать родителю",
  "source": "https://организатор.рф/положение", "verifiedAt": "2026-09-29" }
```

- `region: ""` – для всей страны; иначе точное название субъекта РФ из
  `lib/content/regions.mjs`, и олимпиада видна только этому региону;
- `registrationType: "school"` – записывает школа, `deadline` не нужен; `"link"` – `url` ведёт на
  регистрацию, `deadline` обязателен;
- даты – `ГГГГ-ММ-ДД` или `"expected"` («ожидается»), `deadline` не позже `dateEnd ?? date`;
- региональные выпуски одной олимпиады объединяются общим `series`
  (например, `vsosh-school-2026-math`);
- `source` и `verifiedAt` обязательны по договорённости: каждая дата должна быть сверена с
  официальной страницей.

## 3. Проверки качества

| Проверка | Команда | Что ловит |
|---|---|---|
| Схема и связи | `pnpm compile-content` | всё из `lib/content/validate.mjs`: обязательные поля, форматы дат и ссылок, регион из справочника, тема урока/задания существует и совпадает по классу и предмету, задания пробника, дубли `id`, дубли олимпиад (название + регион + дата) |
| Качество учебного контента | `pnpm exec vitest run --project unit tests/unit/content/` | у каждой темы ≥ 5 уроков и ≥ 5 заданий с разными `order` и своё описание (≥ 20 символов); урок – ≥ 200 символов текста; в теме есть разобранный пример; нет заданий-шаблонов, отличающихся только числами; числовой ответ корректен, разбор ≥ 40 символов; у задачи на код 3–20 тестов, `example` равен первому тесту, **эталонное решение проходит все свои тесты** (нужен `python3`); согласование числительных («3 минуты», а не «3 минут»); `test-data.json` указывает на существующие записи с верными ответами |
| Всё вместе | `pnpm test` | unit + ui, в том числе обе проверки выше |

Пока правите один класс и предмет, ускорьте проверку: `CONTENT_SCOPE=math-4 pnpm exec vitest run --project unit tests/unit/content/`.
Эти проверки идут в CI; ошибка в контенте останавливает и `pnpm build`, и Docker-сборку.

## 4. Как безопасно добавить тему или задание

1. Добавьте тему в `content/topics/<предмет>-<класс>.json` с новым `id` и следующим `order`.
2. Добавьте не меньше 5 уроков и 5 заданий этой темы в соответствующие файлы `lessons/` и
   `tasks/` (класс и предмет можно не писать – возьмутся из темы).
3. Для задачи на код проверьте эталонное решение на всех тестах: это сделает тест качества.
4. `pnpm compile-content` и `CONTENT_SCOPE=<предмет>-<класс> pnpm exec vitest run --project unit tests/unit/content/`.
5. Не меняйте `id` и не удаляйте опубликованные задания, на которые ссылаются пробники или
   `test-data.json`; если меняете правильный ответ задания из `test-data.json`, обновите и его.
6. Закоммитьте. На новом сервере контент загрузится сам (`SEED_MODE=bootstrap`); в работающую
   базу его переносит `scripts/sync-content.mjs` – сначала пробный прогон, потом `--apply`
   ([docs/DEPLOYMENT.md](../docs/DEPLOYMENT.md#7-обновление-контента-и-календаря-в-работающей-базе)).

Небольшие правки проще сделать в админ-панели: она применяет те же правила, сохраняет
историю версий и не требует деплоя. Но тогда правка есть только в базе – чтобы она попала в
репозиторий, перенесите её в `content/`.
