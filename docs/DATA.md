# Данные «Олимпуса»

Где и как хранятся данные, схема таблиц и контента, правила проверки, происхождение календаря,
резервные копии и персональные данные. Архитектура – [ARCHITECTURE.md](ARCHITECTURE.md), формат
файлов контента для авторов – [../content/README.md](../content/README.md).

## 1. Что где хранится

| Данные | Хранилище | В Git |
|---|---|---|
| Олимпиады, темы, уроки, задания, пробники | PostgreSQL, таблица `records` | исходники в `content/`, собранный бандл `lib/seed.json` |
| История версий материалов | `revisions` | нет |
| Сессии (гость, MAX, учитель) | `sessions` | нет |
| Прогресс, звёзды, отметки «Я участвую», черновики кода, попытки пробников, настройки | `progress` | нет |
| Хэши загруженного контента | `imports` | нет |
| Применённые миграции | `_olympus_migrations` | SQL в `drizzle/` |
| Состояние чат-бота | `bot_users`, `bot_reminders` | нет |
| Загруженные учителем файлы | R2-совместимое хранилище (локальная эмуляция) | нет |
| Стандартные картинки и иконки | `public/` | да |

Docker volumes (имя проекта `olympus` локально и `olympus-production` на сервере):

| Volume | Путь в контейнере | Что внутри |
|---|---|---|
| `olympus_postgres_data` / `olympus-production_postgres_data` | `/var/lib/postgresql/data` | вся PostgreSQL |
| `olympus_olympus_media` / `olympus-production_olympus_media` | `/app/.wrangler/state` (web) | загруженные медиа (эмуляция R2) |
| `olympus-production_caddy_data`, `…_caddy_config` | `/data`, `/config` (caddy) | сертификаты Let's Encrypt и настройки Caddy |

`docker compose down` и пересборка образов volumes не трогают. `docker compose down -v` удаляет их
вместе со всеми данными.

## 2. Таблицы PostgreSQL

Миграции `drizzle/0000…0003*.sql` применяет `scripts/postgres-migrate.mjs` при каждом старте
контейнера `web` (новые – по одной, в транзакции). Миграции только добавляют: в production уже есть
данные. Время везде – Unix-миллисекунды (`BIGINT`).

| Таблица | Колонки | Назначение |
|---|---|---|
| `records` | `id TEXT PK`, `kind TEXT` (индекс), `data TEXT` (JSON), `draft TEXT` (JSON или NULL), `updated BIGINT`, `deleted INTEGER 0/1` | Материалы. `data` – то, что видят дети; `draft` – неопубликованная правка учителя; `deleted = 1` – мягкое удаление. Каждая запись строго увеличивает `updated` строки: по нему кэш каталога узнаёт об изменениях ([API.md §4.1](API.md#41-get-apiolympus--bootstrap)) |
| `revisions` | `id TEXT PK`, `record_id TEXT` (индекс), `data TEXT`, `created BIGINT` | Прежние версии: пишутся перед публикацией, удалением и изменением через `sync-content` |
| `sessions` | `token TEXT PK` (SHA-256 токена), `user_id TEXT` (индекс), `name TEXT`, `photo TEXT` (всегда NULL), `admin INTEGER 0/1`, `admin_seen BIGINT`, `expires BIGINT` (индекс) | Сессии; сам токен в базе не хранится |
| `progress` | `user_id TEXT`, `key TEXT`, `data TEXT` (JSON), `updated BIGINT` (индекс); PK `(user_id, key)` | Весь прогресс пользователя, ключи – в §3 |
| `imports` | `id TEXT PK`, `hash TEXT` | SHA-256 каждой записи бандла и всего бандла (`id = 'bundle'`) – для `SEED_MODE` и `sync-content` |
| `_olympus_migrations` | `name TEXT PK`, `applied_at TIMESTAMPTZ` | Какие файлы `drizzle/*.sql` применены |
| `bot_users` | `user_id TEXT PK` (цифры, id MAX), `first_name`, `started_at`, `stopped_at`, `reminders_enabled BOOLEAN`, `updated` | Кто писал боту и согласен ли на напоминания |
| `bot_reminders` | `user_id` → `bot_users` (ON DELETE CASCADE), `olympiad_id`, `kind` (`d3`/`d1`), `sent_at`; PK из трёх полей | Какие напоминания уже отправлены |

**Идентификаторы пользователей** (`progress.user_id`, `sessions.user_id`): `guest:<uuid>` – гость,
`max:<id MAX>` – пользователь MAX, `test:evaluator` – техническая учётная запись API проверяющих.
Бот хранит тот же id MAX без префикса.

## 3. Ключи прогресса

Тип значений – `lib/domain/types.ts`.

| Ключ | Значение | Когда пишется |
|---|---|---|
| `lesson:<lessonId>` | `{ read: true }` | ребёнок открыл урок (`view-lesson`) |
| `task:<taskId>` | `{ title, topicId, subject, correct, lastCorrect, attempts, selfChecked, revealed?, solvedAfterReveal? }` | каждая проверка ответа; `revealed` – открыт разбор до решения |
| `code:<taskId>` | `{ code, language }` | автосохранение программы |
| `registration:<olympiadId>` | `{ registered: true }` | отметка «Я участвую» (снимается удалением ключа) |
| `theory-star:<topicId>` | `{ title, subject, type: "theory", date }` | все уроки темы открыты и звезда получена (`star`) |
| `practice-star:<topicId>` | `{ title, subject, type: "practice", date }` | 3 задания темы решены без просмотра разбора |
| `star:<topicId>` | как выше | старый формат звезды теории, читается для совместимости |
| `attempt:<attemptId>` | попытка пробника целиком: задания на момент старта, ответы, `started`, `ends`, результаты | старт, автосохранение, завершение пробника |
| `settings` | `{ region?, grade?, subject? }` | выбор класса, предмета, региона |

Правила, которые из этого следуют:

- задание, решённое только после открытия разбора, считается решённым (`solvedAfterReveal`), но
  не даёт ни звезды, ни медали (`countsAsSolved` в `lib/domain/achievements.mjs`);
- медали – по предмету, за число самостоятельно решённых заданий: «Первый шаг» (1), «Исследователь»
  (5), «Мыслитель» (15), «Мастер» (30), «Олимпиец» (60);
- попытка пробника хранит снимок заданий на момент старта, поэтому правка задания учителем не
  меняет уже начатую попытку. Скрытые тесты из снимка клиенту не отдаются.

## 4. Схема контента

Одна запись – один JSON-объект с полями `id` и `kind`. В файлах `content/<kind>/` поле `kind`
подставляется по папке. Проверка – `lib/content/validate.mjs`: её используют сборка, админ-панель
и `scripts/sync-content.mjs`, поэтому правила ниже одинаковы везде. Сообщения об ошибках – на
русском и показываются учителю как есть.

### 4.1 Общие поля

| Поле | Правило |
|---|---|
| `id` | обязательно; `^[a-zA-Z0-9_-]{1,100}$`; стабильно – на него ссылаются прогресс и другие записи |
| `kind` | `olympiads`, `topics`, `lessons`, `tasks`, `mock-tests` |
| `title` | обязательно, до 300 символов |
| `grade` | 4, 5 или 6 (строка `"5"` приводится к числу) |
| `subject` | `math` или `info` |
| `order` | целое ≥ 0, порядок внутри темы или класса |
| `demo` | `true` – демонстрационная запись: календарь помечает её значком «Пример», список пробников – «Учебный». В текущем контенте таких записей нет |
| `unpublished` | ставит сервер у черновика, который ни разу не публиковался; при сохранении и импорте из админ-панели поле отбрасывается |

### 4.2 Тема (`topics`)

`grade`, `subject` – обязательны; `description` – до 5000 символов; `order`.

### 4.3 Урок (`lessons`)

| Поле | Правило |
|---|---|
| `topicId` | обязательно, существующая тема |
| `blocks` | 1–200 блоков `{ type, value, caption? }`, `value` – строка до 50 000 символов |
| `grade`, `subject` | можно не указывать: берутся из темы; если указаны – должны совпадать с темой |

Типы блоков: `text`, `example`, `list` (пункты – строки через `\n`), `table`, `formula` (KaTeX),
`code`, `image`, `video`, `link`. У `image`, `video`, `link` значение – ссылка `https://…` или
загруженный файл `/api/media/<id>`.

### 4.4 Задание (`tasks`)

| Поле | Правило |
|---|---|
| `topicId` | обязательно; `grade`/`subject` наследуются от темы и должны с ней совпадать |
| `type` | `number` (числовой ответ), `proof` (рассуждение с самопроверкой), `code` (программа) |
| `prompt` | условие, обязательно, до 50 000 символов |
| `solution` | разбор, обязательно, до 50 000 символов |
| `hint` | подсказка, до 5000 символов; если пусто, ребёнок увидит общую «Разбей условие на шаги и проверь небольшой пример» |
| `answer` | для `number` обязателен: целое или десятичное, знак и `.`/`,` допустимы (`12`, `-3`, `0,5`); до 300 символов |
| `points` | ≥ 0, до 1000; по умолчанию 1 |
| `tests` | для `code` обязательно: 1–20 пар `{ input, output }` (строки до 100 000 символов). Скрытые, клиенту не отдаются |
| `example` | для `code`: публичный пример `{ input, output }`, показывается ребёнку |

Ответ ребёнка на числовое задание сравнивается как число: `0,5` = `0.5`, `+3` = `3`. Вывод
программы сравнивается построчно без хвостовых пробелов, `\r\n` и пустых строк в конце.

### 4.5 Пробник (`mock-tests`)

| Поле | Правило |
|---|---|
| `grade`, `subject` | обязательны |
| `olympiad` | название олимпиады, к которой готовит пробник (до 300 символов), используется как подпись и фильтр |
| `minutes` | 1–600 |
| `taskIds` | 1–200 разных id существующих заданий того же класса и предмета |
| `randomize` | `true` – в каждой попытке случайная выборка |
| `taskCount` | при `randomize` обязателен: от 1 до числа `taskIds` |

### 4.6 Олимпиада (`olympiads`, схема v2)

| Поле | Правило и смысл |
|---|---|
| `subject` | обязательно, основной предмет; `subjects` – необязательный список без повторов, должен включать `subject` |
| `grades` | непустой список без повторов из 4, 5, 6 |
| `format` | `online` или `offline` |
| `region` | `""` – олимпиада для всей страны (при любом формате); иначе точное название из справочника 89 субъектов РФ (`lib/content/regions.mjs`) – олимпиада только этого региона, даже если проходит онлайн |
| `series` | ключ серии региональных выпусков одной олимпиады (`vsosh-school-2026-math`): строчные латинские буквы, цифры, дефисы. Без выбранного региона интерфейс сворачивает серию в одну карточку |
| `stage` | подпись этапа («Школьный этап»), до 300 символов |
| `registrationType` | `link` (по умолчанию): `url` – страница регистрации у организатора; `school`: индивидуальной регистрации нет, участников записывает школа, `url` объясняет, как участвовать |
| `url` | `https://…` или пусто |
| `date` | день проведения (первый день): `ГГГГ-ММ-ДД` или `expected` (также принимаются «ожидается» и `pending`) |
| `dateEnd` | последний день многодневной олимпиады или окна участия; только при точной `date`, не раньше неё |
| `deadline` | дедлайн регистрации: дата или `expected`; обязателен, кроме `registrationType: "school"`; не позже `dateEnd ?? date` |
| `registrationStart` | начало регистрации, дата; не позже дедлайна и окончания |
| `price` | стоимость в рублях, 0–1 000 000; отсутствие – «не указана» |
| `description` | до 5000 символов |
| `image` | `https://…`, `/api/media/<id>` или стандартная картинка |
| `featured` | выделить карточку |
| `source` | официальная страница, по которой сверены даты и ссылка (только `https://`) |
| `verifiedAt` | дата последней сверки с `source`, `ГГГГ-ММ-ДД` |

### 4.7 Правила между записями

- урок и задание ссылаются на существующую тему и совпадают с ней по классу и предмету;
- задания пробника существуют и совпадают с ним по классу и предмету;
- один `id` не может принадлежать записям разных типов;
- **дубль олимпиады** – две записи с разными `id`, у которых совпадают нормализованное название
  (регистр, «ё», кавычки, тире и пробелы не важны), регион и дата. Сборка, публикация и
  `sync-content` такой дубль не пропускают (`409 DUPLICATE_OLYMPIAD` в админке);
- `sync-content` дополнительно не даёт удалить запись, на которую ссылаются оставшиеся.

## 5. Что сейчас в базе и откуда это взялось

Собранный бандл `lib/seed.json` содержит **1305 записей** (`pnpm compile-content` →
«Compiled and validated 1305 content records»):

| Тип | Кол-во | Файлы | Происхождение |
|---|---:|---|---|
| Темы | 72 | `content/topics/{math,info}-{4,5,6}.json` | собственные материалы: 12 тем на каждый класс (4–6) и предмет (математика, информатика) |
| Уроки | 360 | `content/lessons/…` | собственные материалы, по 5 уроков на тему |
| Задания | 360 | `content/tasks/…` | собственные материалы: 264 с числовым ответом, 96 на программирование (со скрытыми тестами) |
| Пробники | 12 | `content/mock-tests/initial.json`, `max-2026.json` | собственные: «Пробный тур» (фиксированные 9–10 заданий, 60–75 минут) и «Большой тур» (12 случайных заданий из 60, 60 минут) для каждого класса и предмета |
| Олимпиады | 501 | `content/olympiads/2026-27.json` | реальный календарь 2026/27, сверенный вручную с официальными источниками (ниже) |

**Смоделированных интеграций нет.** Календарь не подтягивается из внешней информационной системы
автоматически: это заранее подготовленные данные, собранные и проверенные вручную. У каждой
олимпиады есть `source` (официальная страница) и `verifiedAt` (у всех записей – `2026-09-29`).
Демонстрационных записей (`demo: true`) в контенте нет.

### Календарь 2026/27

- **433** записи – школьный этап ВсОШ по регионам (89 субъектов РФ): математика
  (`vsosh-school-2026-math`) и четыре профиля информатики (программирование, ИИ, информационная
  безопасность, робототехника), у двух регионов – одна запись «информатика» без профилей. Тип
  регистрации `school`: записывает школа, дедлайна нет. Даты – по графику «Сириуса»
  (siriusolymp.ru) или региональному графику.
- **68** других олимпиад: 35 всероссийских (`region: ""`) и 33 региональных; 52 по математике,
  15 по информатике, 1 по обоим предметам.
- Онлайн – 459, очно – 42. Даты – с 20.09.2026 по 22.04.2027; у 39 записей дата ещё не объявлена
  организатором (`expected`, в интерфейсе – «Ожидается»).
- Удалены из прежней production-базы 28 записей (дубли, не подходящие по классам, не проводящиеся
  в 2026/27, уже прошедшие) – список с причинами: `scripts/data/olympiad-deletions-2026-09-29.json`.

Источники по умолчанию: siriusolymp.ru (график и группы регионов), vserosolimp.edsoo.ru
(операторы ВсОШ и методические рекомендации; перед использованием проверять, что домен работает и не
перехвачен), vos.olimpiada.ru (Москва), сайты организаторов. olimpiada.ru – только как подсказка,
где искать, но не как источник дат.

### Как поддерживать календарь актуальным

Кто: один редактор контента; правило – у каждой правки есть `source` и новый `verifiedAt`.

| Период | Как часто сверять |
|---|---|
| сентябрь – ноябрь (школьный и муниципальный этапы ВсОШ, старт вузовских отборов) | раз в неделю |
| декабрь – апрель | раз в две недели |
| май – август | раз в месяц |
| конец августа | смена сезона: новые группы и график Сириуса, пересборка записей ВсОШ, ручная проверка регионов вне Сириуса |

Что проверять в первую очередь: записи с «Ожидается» – в месяц, когда организатор обычно
публикует сроки (октябрь – «Ломоносов»; декабрь – ИТМО, Курчатов, ПВГ, «Наглядная геометрия»,
Московская олимпиада по информатике; январь – ВУЗАК, СПб олимпиада по программированию;
февраль – март – весенние региональные); записи с `verifiedAt` старше 30 дней, начиная с
ближайших по дате; «Квантик» – ежемесячно; МетаШкола – в начале января и апреля.

Как вносить: отдельные записи – в админ-панели ([TEACHER-GUIDE.md](TEACHER-GUIDE.md)); массово –
правкой `content/olympiads/*.json` в Git и переносом в работающую базу через
`scripts/sync-content.mjs` ([DEPLOYMENT.md](DEPLOYMENT.md#7-обновление-контента-и-календаря-в-работающей-базе)).

## 6. Тестовые данные

- `test-data.json` – стабильные id для автоматической проверки API: тема `math-4-01`, урок
  `math-4-01-lesson-1`, задание `math-4-01-task-1` (правильный ответ `26`), олимпиада
  `moscow-math-festival-2027`, пробник `mock-4-math` и правильные ответы на все 10 его заданий.
  Все id есть в текущем контенте. Роль – `test_user`. Те же значения записаны в `DATA-API.yaml`;
  их совпадение с контентом проверяют `tests/unit/contracts/data-api.test.ts` и тест качества
  контента.
- Учётная запись `test_user` (`TEST_API_USERNAME` / `TEST_API_PASSWORD`; локально из
  `.env.example` – `test_user` / `olympus-local-test`) пишет прогресс под `test:evaluator`;
  `POST /api/v1/test/reset` очищает только её прогресс. Детские данные она не видит и не меняет.
- `scripts/api-smoke.mjs` (`pnpm test:api`) использует `test-data.json`; если id не опубликован,
  берёт первую запись того же типа и пишет об этом.
- Тесты не зависят от текущего контента: интеграционные тесты работают на маленьком
  синтетическом курсе `tests/support/fixtures.ts` (темы `fx-*`), а `tests/fixtures/*` – снимки
  календаря для проверки валидации и `sync-content`. В приложение они не попадают.

## 7. Резервные копии и восстановление

Команды для локального стенда; на сервере добавьте `-f compose.production.yaml` после
`docker compose`. Файлы складываются в `./backups/` (в Git не попадают).

```bash
# PostgreSQL → backups/olympus-db-ГГГГММДД-ЧЧММСС.dump (pg_dump --format=custom)
docker compose --profile tools run --rm backup

# медиа → backups/olympus-media-ГГГГММДД-ЧЧММСС.tar.gz
docker compose --profile tools run --rm media-backup

# восстановление PostgreSQL из файла в ./backups (заменяет объекты базы содержимым дампа)
docker compose stop web bot
BACKUP_FILE=olympus-db-ГГГГММДД-ЧЧММСС.dump docker compose --profile tools run --rm restore
docker compose start web bot
```

`restore` принимает только имя файла из `./backups` (без `/` и `..`) и выполняет
`pg_restore --clean --if-exists --no-owner --no-privileges`. Перед восстановлением сделайте свежий
`backup`. Медиа восстанавливаются распаковкой архива в volume `olympus_media` (например, через
временный контейнер `alpine` с этим volume). Автоматический деплой (`scripts/deploy/remote-deploy.sh`)
делает `backup` PostgreSQL перед каждым релизом; медиа он не копирует.

Внешняя PostgreSQL: вместо встроенной можно указать `DATABASE_URL` (и `DB_SSL=require` или
`verify-full`); тогда резервное копирование – средствами провайдера.

## 8. Персональные данные

**Что сохраняется о пользователе:**

| Где | Что | Откуда |
|---|---|---|
| `sessions.user_id` | `max:<id пользователя MAX>` или случайный `guest:<uuid>` | подписанные данные запуска MAX / сервер |
| `sessions.name` | имя из профиля MAX (`first_name` и, если MAX его передал, `last_name`) | `initData` |
| `bot_users` | id MAX, `first_name`, время старта/остановки, согласие на напоминания | события бота |
| `progress` | учебные действия: уроки, ответы, код, попытки, звёзды, отметки «Я участвую», выбранные класс, предмет, регион | действия ребёнка |

**Что не сохраняется:** телефон, контакты, фотография профиля (колонка `sessions.photo` всегда
пустая, старые значения очищаются при каждом старте), возраст, адрес, тексты сообщений боту.
Бот не запрашивает контакт. В логах бота из идентификаторов – только id MAX, без имён и текстов.
Пароли пользователям не нужны: вход – через подпись MAX.

**Сроки.** Гостевые сессии – до 365 дней (пустые удаляются через сутки), сессии MAX – 30 дней,
истёкшие удаляются при старте и каждые 6 часов. Автоматического срока удаления прогресса нет (так
и написано в политике в приложении).

**Доступ.** Данные видны только серверу; учитель в админ-панели работает с контентом, а не с
прогрессом детей. Прямой доступ к БД – у администратора сервера.

**152-ФЗ и правила MAX – что остаётся сделать владельцу продукта:**

- заполнить сведения об операторе в `components/olympus/legal/texts.tsx` (`OPERATOR`: наименование,
  ИНН/ОГРН, адрес, e-mail) – сейчас там заглушки «[заполнить: …]», и экран «О приложении» так и
  показывает их (выделенными); этого требуют правила MAX (Требования, п. 2.1);
- решить вопрос согласия законного представителя на обработку данных несовершеннолетних –
  в политике в приложении сказано, что она не заменяет отдельное согласие, когда оно необходимо;
- удаление по запросу выполняется вручную. Для пользователя MAX с id `123`:

  ```sql
  BEGIN;
  DELETE FROM progress  WHERE user_id = 'max:123';
  DELETE FROM sessions  WHERE user_id = 'max:123';
  DELETE FROM bot_users WHERE user_id = '123';   -- напоминания удалятся каскадно
  COMMIT;
  ```

  Выполняется, например, через
  `docker compose -f compose.production.yaml exec postgres psql -U olympus -d olympus`
  (подставьте свои `POSTGRES_USER` и `POSTGRES_DB`).
