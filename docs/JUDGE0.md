# Проверка программ: runner и Judge0

Задания по информатике с `type: "code"` проверяются запуском программы ребёнка на скрытых тестах.
Код никогда не исполняется в контейнере приложения: цепочка такая –

```text
web (lib/services/runner.ts) ──► runner (runner/server.mjs) ──► Judge0 CE (внешняя песочница)
```

## 1. Зачем отдельный runner

`runner` – небольшой HTTP-адаптер без зависимостей (Node 22, `node:http`), собирается из
`runner/Dockerfile`. Он:

- принимает `POST /execute` только с `Authorization: Bearer <RUNNER_TOKEN>` (если токен задан;
  сравнение за постоянное время);
- проверяет язык, размер кода (до 50 000 символов) и тестов (1–20, каждый до 100 000 символов),
  размер запроса (`RUNNER_REQUEST_LIMIT`);
- держит не больше `RUNNER_MAX_CONCURRENT` проверок одновременно, остальным отвечает
  `429 RUNNER_BUSY` с `Retry-After: 2`;
- отправляет каждый тест в Judge0 отдельной посылкой и опрашивает результат (каждые 300 мс, до
  20 секунд на тест);
- сам сравнивает вывод с ожидаемым: построчно, без хвостовых пробелов, `\r\n` и пустых строк в конце;
- при ошибке компиляции, ошибке выполнения или превышении времени прекращает проверку, при неверном
  выводе продолжает и считает пройденные тесты; возвращает `{ correct, output, passed, total }`.

Сам runner присланный код не запускает. Judge0 CE – отдельная платформа со своими воркерами и
песочницей; включать её в compose «Олимпуса» не стали: это резко увеличило бы сборку, требования
к серверу и поверхность атаки. Поэтому Judge0 – **внешний сервис**, который разворачивается
отдельно (официальный репозиторий judge0/judge0, инструкция по установке CE), а воспроизводимой
частью репозитория остаётся runner.

## 2. Лимиты посылки в Judge0

| Параметр | Значение |
|---|---|
| CPU | 2 с |
| Время на стене | 5 с |
| Память | 256 МБ (`memory_limit: 262144` КБ) |
| Максимальный размер файла | 1024 КБ |
| Сеть | выключена (`enable_network: false`) |

Языки: Python 3, C++, Java, JavaScript, Kotlin, Pascal. Runner берёт из `GET /languages` Judge0
самую новую установленную версию каждого (по имени: `Python (3…`, `C++…`, `Java (…`,
`JavaScript…`, `Kotlin…`, `Pascal…`). Если нужного языка в Judge0 нет – ребёнок видит «Этот язык
сейчас недоступен для проверки. Выбери другой язык».

## 3. Что видит ребёнок

| Ситуация | Сообщение |
|---|---|
| все тесты пройдены | `correct: true`, «Пройдено тестов: N из N» |
| вывод не совпал | «Пройдено тестов: K из N» |
| превышено время | «Программа работает слишком долго. Проверь циклы и попробуй решение побыстрее» |
| ошибка компиляции | «Ошибка компиляции:» и текст компилятора |
| ошибка выполнения | «Ошибка во время выполнения:» и stderr – только на первом тесте (публичный пример); на остальных – «Ошибка во время выполнения: Программа завершилась с ошибкой на тесте K», чтобы не раскрыть скрытые входные данные |
| runner занят | «Проверка программ сейчас занята. Попробуй через несколько секунд» (`429 RUNNER_BUSY`) |
| код слишком большой или некорректный | «Программа слишком большая или содержит недопустимые данные» (`422 INVALID_CODE`) |
| runner или Judge0 недоступны, `RUNNER_URL` не задан | «Проверка программ сейчас не работает. Твой код сохранён – попробуй позже.» (`503 RUNNER_UNAVAILABLE`) |

Код сохраняется (`code:<taskId>`) до отправки в runner, поэтому при сбое проверки он не теряется.
Технические тексты runner и Judge0 ребёнку не показываются, только пишутся в лог `web`/`runner`.
Кнопка запуска со своими входными данными (действие `run`) отправляет один тест без ожидаемого
вывода и возвращает то, что напечатала программа.

В пробнике ответы-программы, которые не удалось проверить из-за недоступности проверки, получают
статус «не проверено» (`unchecked`) и 0 баллов до перепроверки; после восстановления проверки их
можно перепроверить в результатах пробника (действие `mock-recheck`).

## 4. Настройка

```env
# web ↔ runner. В локальном compose.yaml RUNNER_URL по умолчанию http://runner:8080,
# в compose.production.yaml он задан всегда.
RUNNER_URL=
RUNNER_TOKEN=<длинная случайная строка; одинаковая для web и runner; обязательна в production>

# только для контейнера runner
JUDGE0_URL=https://<judge0-host>
JUDGE0_AUTH_TOKEN=          # если ваш Judge0 защищён заголовком X-Auth-Token
RUNNER_MAX_CONCURRENT=4     # 1–16
RUNNER_REQUEST_LIMIT=1000000  # байт, 64 000 – 10 000 000
```

Порт runner – `8080` (`RUNNER_PORT`), наружу не публикуется: к нему ходит только `web` по
внутренней Docker-сети. Judge0 должен быть доступен из контейнера runner.

## 5. Состояние и проверка

`GET /health` runner:

| Ответ | Когда | Healthcheck контейнера |
|---|---|---|
| `200 {"status":"ok","judge0":"ok","languages":N}` | Judge0 отвечает | healthy |
| `200 {"status":"degraded","judge0":"not_configured"}` | `JUDGE0_URL` не задан | healthy – остальное приложение работает |
| `503 {"status":"degraded","judge0":"unavailable"}` | `JUDGE0_URL` задан, но Judge0 не отвечает | unhealthy (в production это остановит автодеплой и вызовет откат, см. [DEPLOYMENT.md](DEPLOYMENT.md#5-автоматический-деплой-из-github-cd)) |

```bash
docker compose exec runner node -e "fetch('http://127.0.0.1:8080/health').then(r=>r.text()).then(console.log)"
# сквозная проверка (нужен доступ к порту runner, например из dev-окружения):
RUNNER_URL=http://localhost:8080 RUNNER_TOKEN=<токен> pnpm test:runner
```

`pnpm test:runner` отправляет программу на Python `print(n * 2)` с тестом `2 → 4` и ждёт
`correct: true`.

Флаг `features.runner` в ответе `/api/olympus` означает только, что задан `RUNNER_URL`; работает ли
Judge0, приложение узнаёт при первой проверке.
