# Безопасность

Кратко: от чего защищается «Олимпус», что для этого сделано (со ссылками на код) и что остаётся
сделать. Устройство сессий подробнее – [ARCHITECTURE.md](ARCHITECTURE.md#4-сессии-и-вход),
персональные данные – [DATA.md](DATA.md#8-персональные-данные).

## 1. Модель угроз

| Что защищаем | От чего | Кто может атаковать |
|---|---|---|
| Прогресс и данные ребёнка | чтение и изменение чужого прогресса, подмена пользователя MAX | любой пользователь интернета, другой ученик |
| Контент | правка и удаление материалов без прав учителя; внедрение вредоносных ссылок и HTML через контент | ученик, внешний злоумышленник, ошибка учителя |
| Ответы и скрытые тесты | получение ответов до решения, извлечение скрытых тестов | ученик |
| Сервер | исполнение недоверенного кода, перегрузка, подбор паролей | ученик, внешний злоумышленник |
| Секреты | утечка `BOT_TOKEN`, паролей, `RUNNER_TOKEN` через репозиторий, логи, бэкапы | любой, у кого есть доступ к репозиторию или логам |
| Цепочка поставок | уязвимые или подменённые зависимости, действия CI | внешний злоумышленник |

## 2. Что сделано

### Аутентификация и сессии

- Вход ребёнка – только по подписанным данным MAX: HMAC-SHA256 по алгоритму dev.max.ru, срок
  жизни 1 час, сравнение за постоянное время (`lib/server/max-auth.ts`). Идентификатор MAX берётся
  из подписи, а не из запроса клиента.
- Токен сессии – 32 случайных байта (64 hex-символа, `lib/server/crypto.ts`). В БД хранится только
  его SHA-256; дамп или бэкап не позволяет войти чужой сессией (`drizzle/0003_session_token_hash.sql`).
- Вход учителя: пароль `ADMIN_PASSWORD` (в production ≥ 12 символов), сравнение за постоянное время,
  смена токена после входа, права снимаются после 60 минут бездействия (`lib/server/session.ts`).
- Учётная запись проверяющих `test_user` изолирована: её прогресс пишется под `test:evaluator`,
  сброс затрагивает только её.
- Лимит неудачных входов: 10 ошибок за 15 минут с адреса → блокировка на 15 минут, общий для входа
  учителя и `/api/v1/auth/login` (`lib/server/rate-limit.ts`).

### Запросы и CSRF

- POST без заголовка `Authorization` должен прийти с того же `Origin`, иначе `403 BAD_ORIGIN`;
  запросы с заголовком `Authorization` браузер не отправит с чужого сайта сам.
- Cookie сессии `HttpOnly`, по HTTPS – `Secure; SameSite=None; Partitioned` (работает в iframe
  web.max.ru и не читается скриптами).
- Только `application/json` (иначе `415`), лимит тела 256 КБ (2 МБ для ответов пробника, 12 МБ –
  для импорта и загрузки файлов учителем), проверка каждого поля (`lib/server/validate.ts`),
  id – `^[a-zA-Z0-9_-]{1,100}$`.
- Все ответы API содержат заголовки `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`,
  `Permissions-Policy: camera=(), microphone=(), geolocation=()` (`lib/server/http.ts`).
- Ошибки не раскрывают детали реализации: `500` с общим текстом, подробности – в лог; тексты runner и
  Judge0 клиенту не передаются.

### Контент и то, что видит ребёнок

- Черновики, ни разу не опубликованные и удалённые записи для не-учителя отвечают `404`.
- Задание до решения уходит без ответа, разбора, подсказки и тестов; разбор и ответ – только по
  явному действию (и не во время пробника: `409 MOCK_IN_PROGRESS`); скрытые тесты не уходят
  клиенту никогда, в том числе после пробника. Ошибки выполнения показываются только для первого
  (публичного) теста.
- Таймер пробника – на сервере (`ends` + 5 секунд), ответы после него не принимаются.
- Ссылки в контенте – только `https://` без логина и пароля в URL или загруженные файлы
  `/api/media/…` (`isSafeUrl` в `lib/content/validate.mjs`). Текст уроков выводится как текст, HTML
  не интерпретируется; формулы рендерит KaTeX с `trust: false`.
- Загрузка файлов: только PNG, JPEG, WebP, PDF, MP4 до 8 МБ, тип проверяется по сигнатуре файла, а
  не по заявленному `Content-Type`; файлы отдаются с `nosniff` и типом из белого списка
  (`lib/services/media.ts`).

### Проверка кода

- Код ребёнка не исполняется ни в `web`, ни в `runner`: только в Judge0 с лимитами CPU 2 с,
  wall 5 с, память 256 МБ, без сети.
- Runner доступен только во внутренней сети, требует `Authorization: Bearer <RUNNER_TOKEN>`
  (сравнение за постоянное время; в production без токена `web` не стартует), ограничивает размер
  запроса и число параллельных проверок.
- Контейнер runner: `read_only`, `tmpfs /tmp` с `noexec`, `cap_drop: ALL`, `no-new-privileges`,
  `pids_limit: 64`, 256 МБ памяти, 1 CPU, пользователь `node`.

### Бот

- Webhook принимается только с верным `X-Max-Bot-Api-Secret` (сравнение за постоянное время);
  лимит тела запроса, `413`/`401`/`405` на всё лишнее.
- Бот только читает таблицы приложения и пишет в свои; не запрашивает телефон; в логах нет токена,
  секрета, имён и текстов сообщений.
- Контейнер бота: `read_only`, `cap_drop: ALL`, `no-new-privileges`, пользователь `node`, 256 МБ.
- TLS до `platform-api2.max.ru` проверяется: в образ добавлен публичный корневой сертификат
  Минцифры (`NODE_EXTRA_CA_CERTS`), проверка сертификатов не отключается.

### Инфраструктура

- Наружу открыты только `80/443` Caddy; PostgreSQL, web, runner и бот – во внутренней сети.
- Caddy: HTTPS с автоматическим сертификатом, HSTS, `nosniff`, `Referrer-Policy`,
  `Permissions-Policy`, без заголовка `Server`. `X-Frame-Options` и `frame-ancestors` намеренно не
  ставятся – web.max.ru встраивает мини-приложение в iframe.
- Caddy перезаписывает `X-Real-IP` адресом TCP-клиента и удаляет присланные клиентом
  `X-Forwarded-For`, `Cf-Connecting-Ip`, `True-Client-Ip` – лимитер входа нельзя обойти подменой
  заголовка.
- Production-старт проверяет секреты: `ADMIN_PASSWORD` и `TEST_API_PASSWORD` ≥ 12 символов и не
  равны локальным паролям из `.env.example` (`olympus-local-admin`, `olympus-local-test`), пароль
  БД ≥ 16 символов и не равен локальному, есть `BOT_TOKEN`, есть `RUNNER_TOKEN`
  (`scripts/docker-start.mjs`).

### Секреты

- В репозитории нет рабочих токенов и паролей: `.env.example` – шаблон, в нём только пароли для
  локальной проверки, которые production отвергает; `.env*`, `*.pem`, `*.dump`, `backups/` – в
  `.gitignore` и `.dockerignore`.
- Секреты не попадают в логи: wrangler получает их как `secrets.required` и показывает «(hidden)»
  (`scripts/lib/worker-vars.mjs`); бот и runner их не печатают.
- CI и деплой: секреты сервера – в GitHub Secrets; SSH со строгой проверкой ключа хоста
  (`StrictHostKeyChecking=yes`, `known_hosts` из секрета); вход в GHCR – временным токеном запуска,
  после деплоя `docker logout`. Права workflow минимальные (`contents: read`, `packages: write`
  только у публикации).

### Зависимости и анализ кода

- Все версии зафиксированы `pnpm-lock.yaml`; установка – `--frozen-lockfile`.
- `pnpm-workspace.yaml`: пакеты моложе 7 дней не ставятся (`minimumReleaseAge`), сборочные скрипты
  разрешены только списку `allowBuilds`, `overrides` поднимают уязвимые транзитивные `undici`
  (7.29.1) и `ws` (8.21.3) у `wrangler`/`miniflare`.
- CI: `pnpm audit --prod --audit-level high` (на 29.09.2026 – одна уязвимость уровня low, высоких
  нет), ESLint без предупреждений, `actionlint` для workflow.
- CodeQL (`.github/workflows/codeql.yml`): JavaScript/TypeScript и GitHub Actions, набор
  `security-and-quality`, на каждый push/PR и еженедельно.
- Dependabot: npm (раз в неделю, с задержкой 7 дней, как `minimumReleaseAge`), GitHub Actions и
  базовые Docker-образы (`/` и `/runner`).

## 3. Что остаётся (известные риски)

| Риск | Сейчас | Что сделать |
|---|---|---|
| Один общий пароль учителя | все учителя входят одним `ADMIN_PASSWORD`, в истории версий не видно, кто правил | учётные записи учителей и журнал действий |
| Лимитер входа в памяти | сбрасывается при перезапуске `web`, не делится между экземплярами | общий счётчик в PostgreSQL/Redis при масштабировании |
| Нет общего ограничения частоты запросов | ограничены только входы и проверка кода (параллельность runner) | лимиты на уровне Caddy или приложения |
| Без Caddy `X-Real-IP` задаёт клиент | в локальном Docker лимитер можно обойти | в production запускать только за Caddy (так и настроено) |
| Контейнер `web` работает от root и не read-only | ограничения есть у runner и бота, у web – нет | пользователь `node`, `read_only` с записью только в volume медиа |
| Нет Content-Security-Policy | защищает отсутствие HTML в контенте и KaTeX `trust: false` | добавить CSP с `frame-ancestors https://web.max.ru` и проверить на всех клиентах MAX |
| Бэкапы не шифруются и лежат на том же сервере | `backups/*.dump` | копировать наружу, шифровать |
| Удаление данных по запросу – вручную | SQL в [DATA.md](DATA.md#8-персональные-данные) | действие «удалить мои данные» |
| Правовые реквизиты оператора не заполнены | заглушки в `components/olympus/legal/texts.tsx` | заполнить до публикации (правила MAX, п. 2.1) |
| Поведение cookie и хранилищ в клиентах MAX не проверено на всех устройствах | сессия работает через заголовок `Authorization` | проверить на iOS, Android, desktop ([MAX-INTEGRATION.md](MAX-INTEGRATION.md)) |

Сообщить об уязвимости: напишите владельцам репозитория через приватный канал (GitHub Security
Advisories), не в открытый issue.
