# Интеграция с MAX

Что «Олимпус» использует из платформы MAX, где это в коде, какие есть особенности веб-версии и что
можно подтвердить только с настоящим токеном бота и на реальных устройствах. Сверено с
документацией dev.max.ru и кодом официальной библиотеки `max-web-app.js` на 29.09.2026.

## 1. Как пользователь попадает в «Олимпус»

```text
MAX: чат с ботом «Олимпус»
  ├─ кнопка мини-приложения в чате (URL задаётся в business.max.ru → Чат-боты → Настройки)
  ├─ кнопка open_app в сообщении бота (payload → start_param мини-приложения)
  ├─ ссылка https://max.ru/<имя_бота>?startapp=<payload>  – сразу мини-приложение
  └─ ссылка https://max.ru/<имя_бота>?start=<payload>     – чат с ботом (событие bot_started)
```

Бот проекта – https://max.ru/t605_hakaton_max_bot (`MAX_BOT_NAME=t605_hakaton_max_bot`).
Мини-приложение подключено к чат-боту и без него не используется: бот ведёт в нужные экраны
приложения, а приложение ссылками «Открыть в MAX» и «Поделиться» ведёт обратно в MAX.

## 2. Что используется и где

### 2.1 MAX Bridge (`window.WebApp`)

Подключение – `<script src="https://st.max.ru/js/max-web-app.js">` в `app/layout.tsx`, синхронно
и до старта приложения (библиотека читает данные запуска из `location.hash` в момент выполнения).
Обёртка – `lib/client/max-bridge.ts`; вне MAX каждый вызов ничего не делает или использует
браузерный запасной путь, Promise-методы не бросают ошибок.

| Возможность | Что делает «Олимпус» | Где |
|---|---|---|
| `initData` | обменивается на серверную сессию `max:<id>` (действие `session`) | `state/data.tsx` → `lib/services/auth.ts` |
| `initDataUnsafe.start_param`, `WebAppStartParam`, `?startapp=` | открывает экран: олимпиаду, тему, пробник, вкладку | `AppShell.tsx`, `lib/ui/navigation.ts` (`parseStartParam`) |
| `platform` | тема MAX UI под iOS/Android; вибрация только на iOS и Android | `App.tsx`, `max-bridge.ts` |
| `ready()` | сообщает MAX, что первый экран готов (веб-клиент ждёт до 15 с) | `AppShell.tsx` |
| `BackButton.show/hide/onClick/offClick` | системная кнопка «Назад» ведёт по вложенным экранам приложения, а не закрывает его | `state/navigation.tsx` |
| `openLink`, `openMaxLink` | внешние ссылки (сайты олимпиад) и ссылки `max.ru` открываются средствами MAX – в iframe web.max.ru `window.open` ограничен песочницей | `openExternal` в `max-bridge.ts` |
| `enableClosingConfirmation` / `disableClosingConfirmation` | вопрос перед закрытием приложения во время пробника | `mocks/MockAttemptScreen.tsx` |
| `shareMaxContent` | кнопка «Поделиться» результатом пробника со ссылкой `https://max.ru/<бот>?startapp=mock_<id>` | `mocks/MockResults.tsx` |
| `HapticFeedback.*` | лёгкая вибрация на ответы и переходы (iOS/Android) | экраны учёбы, пробников, онбординга |
| `getLaunchContext()` | если приложение открыто из таб-бара MAX, панель разделов переносится наверх | `AppShell.tsx` |

Не используются, потому что их нет ни в документации, ни в библиотеке: `MainButton`,
`SettingsButton`, `expand`, `themeParams`, события смены темы и safe area. Тема берётся из
`prefers-color-scheme`.

### 2.2 MAX UI

`@maxhub/max-ui` 0.5: провайдер `MaxUI` (с платформой из Bridge), `Button`, `CellList`,
`CellSimple`, `CellHeader`, `CellAction`, `Input`, `Switch`, `Spinner`, `Counter`, `Avatar`,
иконки, хук `useAppearance`. Вкладок, нижней навигации и модальных окон в MAX UI нет – они
собственные (`components/olympus/shared`).

### 2.3 Проверка `initData` на сервере

`lib/server/max-auth.ts` – официальный алгоритм: `secret = HMAC_SHA256("WebAppData", BOT_TOKEN)`,
подпись – `hex(HMAC_SHA256(secret, отсортированные пары key=value через \n))`, срок 1 час. Принимается
подпись, совпавшая при любом из двух прочтений `+` (официальные примеры SDK расходятся). Сервер
возвращает клиенту **подписанный** `start_param`, поэтому экран открывается по данным, которые
подтвердил MAX. Без `BOT_TOKEN` действие `session` отвечает `503 MAX_NOT_CONFIGURED`, а приложение
продолжает работать в гостевом режиме.

### 2.4 Bot API

Клиент – `bot/api.mjs`: `https://platform-api2.max.ru`, заголовок `Authorization: <токен>` (без
`Bearer`), лимит 25 запросов/с на бота и 1 сообщение/с в чат (документация: 30 и 2), повторы при
`429`/`5xx` с экспоненциальной задержкой и учётом `Retry-After`.

| Метод | Зачем |
|---|---|
| `GET /me` | проверка токена, имя бота для кнопок `open_app` |
| `PATCH /me/commands` | меню команд `/start`, `/calendar`, `/progress`, `/reminders`, `/help` |
| `POST /messages` | ответы и (если разрешены) напоминания |
| `POST /answers` | ответ на нажатие кнопки: сообщение редактируется, чат не засоряется |
| `GET /updates` | long polling при локальной разработке |
| `GET/POST/DELETE /subscriptions` | webhook в production (`https://<домен>/max/webhook`, секрет в `X-Max-Bot-Api-Secret`) |

TLS-сертификат `platform-api2.max.ru` выпущен «Russian Trusted Sub CA», поэтому контейнер бота
запускается с публичным корневым сертификатом Минцифры (`bot/certs/russian_trusted_root_ca.crt`,
`NODE_EXTRA_CA_CERTS`). Подробно о боте – [BOT.md](BOT.md).

## 3. Диплинки и `start_param`

| Payload | Куда ведёт в мини-приложении | Кто формирует |
|---|---|---|
| `event_<id>` | карточка олимпиады | бот (кнопки у олимпиад и в напоминаниях) |
| `mock_<id>` | пробник | бот (напоминание), «Поделиться» результатом пробника |
| `topic_<id>` | тема в «Учёбе» | можно использовать во внешних ссылках |
| `tab_home`, `tab_calendar`, `tab_learn`, `tab_mocks`, `tab_profile` | вкладка «Главная», «Олимпиады», «Учёба», «Пробники», «Я» | бот (`tab_calendar`, `tab_training`, `tab_profile`) |
| `tab_knowledge`, `tab_training` | «Учёба» (старые имена вкладок) | бот |

Формат payload: `[A-Za-z0-9_-]`, до 512 символов для `startapp` и до 128 для `start` (иначе MAX
его отбрасывает). В payload нет персональных данных. Для бота `?start=` понимает также `calendar`,
`progress`, `reminders`, `help` – раздел открывается сразу после приветствия.

## 4. Веб-версия web.max.ru

В документации MAX этого нет; ниже – по коду веб-клиента и библиотеки, проверено на 29.09.2026:

1. **iframe с `credentialless`.** Мини-приложение – кросс-сайтовый iframe; в Chromium у него
   эфемерные cookie и хранилища. Поэтому сессия передаётся заголовком `Authorization: Bearer`
   (токен в памяти и `sessionStorage`), а при потере токена пользователь MAX снова входит по
   `initData` без участия ребёнка. Cookie `SameSite=None; Secure; Partitioned` – запасной путь.
   Прогресс всегда хранится на сервере.
2. **Нет `X-Frame-Options` и `frame-ancestors`.** Caddy намеренно их не ставит, иначе web.max.ru
   не сможет встроить приложение.
3. **Песочница iframe** разрешает попапы, но не выход из песочницы и не навигацию верхнего окна –
   поэтому внешние ссылки открываются через `WebApp.openLink`.
4. **Разрешения.** MAX разрешает iframe камеру, микрофон и геолокацию; «Олимпусу» они не нужны,
   Caddy отключает их заголовком `Permissions-Policy`.
5. **Таймаут 15 секунд** на `onload`/`WebAppReady` – приложение вызывает `ready()` после первого
   осмысленного экрана.
6. **Вибрация** в web.max.ru не поддерживается (Promise отклоняется), поэтому вызывается только на
   iOS и Android.

## 5. Требования MAX, которые учтены

- HTTPS для мини-приложения и webhook (Caddy, порт 443).
- Правила контента, п. 1.5: сервисные сообщения и рассылки через API – только по договору с MAX.
  Напоминания бота реализованы, но выключены (`BOT_REMINDERS=off`), а при включении пишут только
  тем, кто сам их включил, и только об олимпиадах из «Моих олимпиад».
- П. 2.1: в приложении есть «О приложении», «Политика конфиденциальности», «Условия
  использования» и возрастная маркировка «6+». Реквизиты оператора – заглушки, их нужно
  заполнить ([DATA.md](DATA.md#8-персональные-данные)).
- П. 4.2: очки, звёзды, попытки и таймер пробника считаются на сервере.
- Персональные данные: из данных MAX сохраняются только id и имя, телефон и фото не
  запрашиваются и не хранятся.

## 6. Что нужно проверить с настоящим токеном и на устройствах

Проверено без устройств: формат запросов Bot API по официальной OpenAPI-схеме, TLS до
`platform-api2.max.ru`, ответ `401 verify.token` на неверный токен, весь сценарий бота на фейковом
API и настоящей PostgreSQL, проверка подписи `initData` на эталонных данных.

**Не подтверждено** (всё настраивается без правки кода):

1. Какое значение ждёт `open_app.web_app`: `username` бота из `GET /me` (по схеме – «public name of
   the bot»). Если кнопка не открывает приложение – задайте `MAX_BOT_NAME` явно.
2. Приходит ли `payload` кнопки `open_app` в мини-приложение как `start_param` на iOS и Android
   (в web.max.ru – да, по коду клиента).
3. Совпадает ли `user.id` из `initData` с `user_id` в событиях бота (иначе «Мой прогресс» в боте
   покажет общий вид вместо данных ребёнка).
4. Появляются ли команды из `PATCH /me/commands` (имена без `/`) в меню команд.
5. Как отображается экранирование markdown в названиях олимпиад (`C++`, `*`, `_`).
6. Можно ли по договору отправлять напоминания (п. 1.5) – до ответа MAX `BOT_REMINDERS=off`.
7. Обновляет ли повторный `POST /subscriptions` на тот же URL подписку, а не создаёт вторую.
8. Сохраняется ли очередь long polling после перезапуска (для production используется webhook).
9. Как ведут себя cookie и хранилища в мобильном WebView MAX и в desktop-клиенте (iframe или
   WebView), работает ли `SameSite=None; Partitioned` в Safari и Firefox. Сессия от этого не
   зависит – она передаётся заголовком.
10. Нужен ли `ready()` мобильным клиентам и есть ли у них safe-area отступы.
11. Минимальный возраст пользователя MAX и требования к детским приложениям – юридический вопрос.

Как проверить: `docker compose exec bot node bot/scripts/smoke.mjs` (токен и имя бота, подписки,
готовые диплинки; `--send-to=<ваш user_id>` – тестовое приветствие себе), затем «Начать» в чате с
ботом → «Ближайшие олимпиады» → кнопка у олимпиады должна открыть её карточку в приложении.
