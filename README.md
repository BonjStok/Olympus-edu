# Олимпус

Чат-бот и мини-приложение в MAX для подготовки школьников 4–6 классов к олимпиадам по математике
и информатике: календарь олимпиад 2026/27 с понятным «как участвовать», короткие уроки и задачи
по темам, пробные туры на время и прогресс, который виден ребёнку и родителю.

Подробная документация – в [docs/](docs/README.md).

| | |
|---|---|
| Production | https://olympus-edu.ru (API: https://olympus-edu.ru/api/v1) |
| Чат-бот в MAX | https://max.ru/t605_hakaton_max_bot |
| Запуск локально | `docker compose up -d --build` → http://localhost:3000 |
| Для ребёнка и родителя | [docs/USER-GUIDE.md](docs/USER-GUIDE.md) |
| Для учителя | [docs/TEACHER-GUIDE.md](docs/TEACHER-GUIDE.md) |

## 1. Назначение решения

**Проблема.** Ребёнок 10–12 лет и его родитель хотят участвовать в олимпиадах, но информация
разбросана по десяткам сайтов организаторов и региональных операторов, условия зависят от класса и
региона, а порядок записи разный: где-то регистрируется сам участник, где-то – только школа. Сроки
легко пропустить, а готовиться к формату олимпиады (задачи на время, программирование) негде в
одном месте.

**Что делает «Олимпус»:**

- **календарь 501 олимпиады** сезона 2026/27 (школьный этап ВсОШ по 89 регионам и 68 других
  олимпиад), каждая запись сверена с официальным источником; фильтр по классу, предмету и региону,
  для каждой – «Зарегистрироваться на сайте» или «Записывает школа – спроси учителя или классного
  руководителя»;
- **учёба:** 72 темы, 360 уроков и 360 задач (из них 96 – на программирование) с мгновенной
  проверкой, подсказками, разбором, звёздами и медалями;
- **12 пробников** – туры на время, как на олимпиаде, с разбором после финиша;
- **профиль:** «Мои олимпиады», прогресс, история пробников; вход через MAX – прогресс одинаков на
  всех устройствах;
- **чат-бот:** ближайшие олимпиады и прогресс в чате, кнопки открывают нужный экран
  мини-приложения;
- **кабинет учителя:** добавление и правка материалов, черновики, история версий, импорт олимпиад
  из таблицы.

**Для кого:** ученики 4–6 классов, которые готовятся к олимпиадам по математике и информатике; их
родители; учителя и методисты, которые ведут календарь и учебные материалы.

## 2. Основной пользовательский сценарий

1. Ребёнок (или родитель) открывает чат-бота «Олимпус» в MAX и нажимает «Начать» → «Открыть
   Олимпус». Вход происходит сам, по подписанным данным MAX.
2. На первом экране выбирает класс, предмет и регион.
3. В разделе «Олимпиады» видит олимпиады своего класса и региона, открывает карточку и узнаёт, как
   участвовать: регистрируется на сайте организатора или узнаёт у учителя, что записывает школа.
   Отмечает «Я участвую» – олимпиада появляется на главной и в профиле.
4. В «Учёбе» проходит тему: читает уроки (звезда за теорию), решает задачи с проверкой ответа,
   подсказкой и разбором (звезда за практику – 3 задачи самостоятельно). Задачи по информатике –
   программы на Python, C++, Java, JavaScript, Kotlin или Pascal, проверяются на скрытых тестах.
5. В «Пробниках» проходит тур на время и получает результат с разбором каждого задания.
6. В разделе «Я» видит звёзды, медали, «Мои олимпиады» и историю пробников; прогресс сохраняется на
   сервере и доступен на телефоне и компьютере.
7. То же без открытия приложения – в чате с ботом: `/calendar` (ближайшие олимпиады по классу и
   региону) и `/progress` (прогресс и «Мои олимпиады»). Бот показывает данные того профиля MAX, из
   которого ему пишут, поэтому родитель смотрит их вместе с ребёнком.
8. Учитель в кабинете («Я» → «Для учителя») обновляет календарь и материалы – дети сразу видят
   опубликованные изменения.

## 3. Состав и архитектура решения

```text
          MAX: iOS · Android · desktop · web.max.ru
   чат-бот «Олимпус»                        мини-приложение (WebView / iframe)
          │ webhook                                 │ HTTPS
          ▼                                         ▼
   ┌───────────────── Caddy :80 / :443 (только production) ──────────────────┐
   │  /max/webhook* → bot:8090                  остальное → web:3000         │
   └──────┬─────────────────────────────────────────┬────────────────────────┘
          ▼                                         ▼
   bot (Node 26)                            web: vinext + React 19 в workerd
   ─► platform-api2.max.ru                  (wrangler dev в Node 26)
          │                                         │
          │ SQL                                     ├── HTTP + RUNNER_TOKEN ──► runner:8080
          │                                         │                              │
          └──────────► PostgreSQL 17 ◄──── SQL ─────┘                              ▼
                       (volume postgres_data)                               Judge0 CE (внешний)
```

| Компонент | Что делает | Код |
|---|---|---|
| `web` | интерфейс мини-приложения и кабинета учителя, RPC `/api/olympus` для интерфейса, REST `/api/v1` для проверки, выдача загруженных файлов | `app/`, `components/`, `lib/`, `Dockerfile` |
| `postgres` | контент, история версий, сессии, прогресс, состояние бота | `drizzle/*.sql` |
| `runner` | принимает программу, отправляет её в Judge0, сравнивает вывод со скрытыми тестами; сам код не исполняет | `runner/` |
| `bot` | чат-бот MAX (тот же образ, что `web`) | `bot/`, [docs/BOT.md](docs/BOT.md) |
| `caddy` | HTTPS, заголовки безопасности, маршрут webhook (только `compose.production.yaml`) | `Caddyfile` |
| Judge0 CE | песочница для запуска кода (разворачивается отдельно) | [docs/JUDGE0.md](docs/JUDGE0.md) |

Подробно: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 4. Запуск всех локальных компонентов одной командой через Docker

Нужен Docker с Compose (раздел 5). Один раз создайте `.env` из шаблона – менять в нём для
локальной проверки ничего не нужно:

```bash
cp .env.example .env
```

В шаблоне уже есть пароли **только для локальной проверки**: кабинет учителя –
`olympus-local-admin`, API – `test_user` / `olympus-local-test`. Production с ними не
запустится (`scripts/docker-start.mjs`).

Запуск всех локальных компонентов (`postgres`, `web`, `runner`, `bot`):

```bash
docker compose up -d --build
```

Откройте http://localhost:3000. Проверка состояния: `docker compose ps` – у всех четырёх сервисов
`(healthy)`; `curl http://localhost:3000/api/v1/health` →
`{"status":"ok","database":"ok","version":"1.0.0"}`.

При первом старте `web` сам применяет миграции и загружает весь контент (1305 записей) в пустую
базу. PostgreSQL отдельно ставить не нужно.

**Что работает сразу, без секретов:** весь интерфейс ребёнка в браузере (гостевой режим):
календарь, уроки, задачи с числовым ответом, пробники, профиль; с `.env` из шаблона – ещё кабинет
учителя и API для проверки. Без `.env` стек тоже запустится, но пароли будут пустыми и эти две
функции ответят `503`. **Что требует внешних значений:**

| Функция | Что нужно |
|---|---|
| вход через MAX и чат-бот | `BOT_TOKEN` бота в MAX, а для мини-приложения ещё и публичный HTTPS-адрес |
| проверка программ | `JUDGE0_URL` – адрес развёрнутого Judge0 CE |

Сервер с HTTPS: `docker compose -f compose.production.yaml up -d --build` – см.
[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## 5. Необходимые параметры окружения

| Параметр | Требование |
|---|---|
| ОС | Linux, macOS или Windows с Docker Desktop / Docker Engine |
| Docker | Engine ≥ 25 и Docker Compose ≥ 2.24 (используются `env_file.required` и `healthcheck.start_interval`) |
| Свободный порт | `3000` на машине (меняется `OLYMPUS_PORT`) |
| Ресурсы | работающий стек занимает около 0,6 ГБ RAM (web ≈ 0,5 ГБ; runner и бот ограничены 256 МБ каждый), образы – около 1,2 ГБ диска; для сборки рекомендуем выделить Docker не меньше 4 ГБ RAM |
| Интернет при сборке | скачать базовые образы `node:26-bookworm-slim`, `postgres:17-alpine` и npm-пакеты по lockfile |
| Интернет при работе | браузер загружает `https://st.max.ru/js/max-web-app.js` (MAX Bridge; вне MAX он ничего не делает); бот обращается к `platform-api2.max.ru`; runner – к Judge0 |
| Production | домен, открытые порты 80/443, токен бота MAX, пароли в `.env` ([docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)) |

CI проверяет, что сборка всех образов с нуля (`docker compose build --no-cache`) укладывается в
300 секунд без учёта первой загрузки базовых образов.

## 6. Переменные окружения

Шаблон – [`.env.example`](.env.example) (без рабочих значений). `.env` в Git не попадает.
«Prod» – обязательна ли в production (`OLYMPUS_ENV=production`, так запускает
`compose.production.yaml`); проверки выполняет `scripts/docker-start.mjs` при старте.

| Переменная | Prod | По умолчанию | Назначение |
|---|---|---|---|
| `OLYMPUS_ENV` | – | `development` | `development` или `production`; production-compose задаёт `production` сам |
| `OLYMPUS_PORT` | – | `3000` | порт на машине для `web` (только локальный compose) |
| `OLYMPUS_DOMAIN` | да | – | домен без `https://` для Caddy и адреса webhook |
| `POSTGRES_DB` / `POSTGRES_USER` | – | `olympus` / `olympus` | имя базы и пользователя PostgreSQL |
| `POSTGRES_PASSWORD` | да, ≥ 16 символов | `olympus_local_dev` (локально) | пароль PostgreSQL; задаётся до первого запуска |
| `DATABASE_URL` | – | пусто | внешняя PostgreSQL вместо встроенной (имеет приоритет над `DB_*`) |
| `DB_SSL` | – | `false` | `require` / `verify-full` для внешней БД; в compose для `web` и `bot` зафиксирован `false` |
| `SEED_MODE` | – | `bootstrap` | загрузка контента при старте: `bootstrap` (только в пустую базу), `sync` (обновить изменённое), `off` |
| `ADMIN_PASSWORD` | да, ≥ 12 символов, не локальный | `olympus-local-admin` в `.env.example` (только локально) | пароль кабинета учителя; пусто – вход учителя отключён (`503`) |
| `BOT_TOKEN` | да | пусто | токен бота MAX: проверка входа в мини-приложение и работа бота; пусто – гостевой режим, бот в режиме `disabled` |
| `MAX_BOT_NAME` | рекомендуется | `t605_hakaton_max_bot` | публичное имя бота для «Открыть в MAX», «Поделиться» и кнопок бота; пусто – приложение эти ссылки не показывает, бот берёт имя из `GET /me` |
| `BOT_REMINDERS` | – | `off` | напоминания бота об олимпиадах; включать только после согласования с MAX |
| `BOT_MODE` | – | `polling` локально, `webhook` в production | способ получения событий ботом: `webhook`, `polling`, `off` |
| `BOT_WEBHOOK_URL` | – | `https://$OLYMPUS_DOMAIN/max/webhook` в production | публичный HTTPS-адрес webhook (порт 443) |
| `BOT_WEBHOOK_SECRET` | да (webhook) | пусто | секрет webhook, 5–256 символов `A-Z a-z 0-9 _ -` |
| `TEST_API_USERNAME` | – | `test_user` | логин учётной записи для проверки API |
| `TEST_API_PASSWORD` | да, ≥ 12 символов, не локальный | `olympus-local-test` в `.env.example` (только локально) | её пароль; пусто – `/api/v1` отвечает `503` (кроме `health`) |
| `RUNNER_URL` | задан в compose | `http://runner:8080` в compose | адрес runner для `web` |
| `RUNNER_TOKEN` | да | пусто | общий секрет `web` ↔ `runner` (локально можно не задавать) |
| `JUDGE0_URL` | для проверки кода | пусто | адрес Judge0 CE; пусто – runner в режиме `degraded`, проверка кода отвечает `503` |
| `JUDGE0_AUTH_TOKEN` | – | пусто | токен Judge0 (`X-Auth-Token`), если он включён |
| `RUNNER_MAX_CONCURRENT` | – | `4` | одновременных проверок кода (1–16) |
| `RUNNER_REQUEST_LIMIT` | – | `1000000` | максимальный размер запроса к runner, байт |

Служебные переменные: `DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASSWORD`/`DB_NAME` compose выставляет
сам из `POSTGRES_*` (нужны только при запуске без Docker); `OLYMPUS_IMAGE_PREFIX` и
`OLYMPUS_IMAGE_TAG` задают имена образов (использует автодеплой); `BACKUP_FILE` – имя дампа для
восстановления. Дополнительные настройки бота (`BOT_LOG_LEVEL`, `BOT_COMMANDS`,
`BOT_RATE_LIMIT_RPS` и др.) – в [docs/BOT.md](docs/BOT.md#4-переменные-окружения).

## 9. Внешние сервисы и интеграции

Приложение использует два внешних сервиса из таблицы ниже. Аналитики, рассылок и сторонних API
данных нет.

| Сервис | Зачем | Можно ли воспроизвести в Docker | Что нужно для проверки |
|---|---|---|---|
| **Платформа MAX** – Bot API (`platform-api2.max.ru`), клиенты MAX, MAX Bridge (`st.max.ru/js/max-web-app.js`) | чат-бот; запуск мини-приложения в MAX; подписанный вход пользователя (`initData`); диплинки, «Поделиться», системная кнопка «Назад» | нет – это внешняя платформа | токен бота (`BOT_TOKEN`), публичный HTTPS-адрес приложения, указанный в настройках бота на business.max.ru; для webhook – `BOT_WEBHOOK_SECRET`. Проверка – в клиенте MAX по ссылке на бота |
| **Judge0 CE** | песочница для запуска программ ребёнка (задачи по информатике) | не входит в compose: отдельная платформа со своими воркерами; runner из compose подключается к ней | развёрнутый Judge0 CE, доступный из контейнера runner, и `JUDGE0_URL` (+ `JUDGE0_AUTH_TOKEN`) |

**Без MAX:** приложение полностью работает в обычном браузере в гостевом режиме; бот стартует в
режиме `disabled` и отвечает только на `/health`. **Без Judge0:** runner стартует в режиме
`degraded`, всё, кроме проверки программ, работает; при проверке ребёнок видит «Проверка программ
сейчас не работает. Твой код сохранён – попробуй позже.», а в пробнике такие ответы получают
статус «Не проверено» и перепроверяются позже.

Что из MAX используется и что можно подтвердить только с настоящим токеном – в
[docs/MAX-INTEGRATION.md](docs/MAX-INTEGRATION.md).

**Календарь олимпиад не подключён к внешним информационным системам.** Это заранее подготовленные
данные: 501 запись, вручную сверенная с официальными сайтами организаторов и региональных
операторов 29.09.2026 (у каждой – поля `source` и `verifiedAt`). Интеграции с системами
организаторов нет и не имитируется; кнопка «Я участвую» – отметка для ребёнка, а не регистрация.

## 10. Описание работы с данными

- **Хранилище** – PostgreSQL 17 в volume `olympus_postgres_data`; загруженные учителем файлы – в
  отдельном volume `olympus_olympus_media` (эмуляция R2).
- **Таблицы:** `records` (материалы как JSON, черновик, мягкое удаление), `revisions` (история
  версий), `sessions`, `progress` (прогресс «пользователь + ключ → JSON»), `imports` (хэши
  загруженного контента), `_olympus_migrations`, `bot_users`, `bot_reminders`.
- **Миграции** `drizzle/*.sql` применяются автоматически при старте `web`, только добавляющие.
- **Контент** хранится в Git (`content/**`), проверяется и собирается в `lib/seed.json` при сборке,
  загружается в пустую базу при первом старте (`SEED_MODE=bootstrap`). Правки учителей в
  кабинете не перезаписываются обычным деплоем; новая версия контента переносится в работающую
  базу командой `scripts/sync-content.mjs` (сначала пробный прогон, потом `--apply`, прежние версии
  сохраняются).
- **Персональные данные – минимум:** из MAX сохраняются только id пользователя и имя из профиля
  (для приветствия). Телефон, фото, возраст, адрес не запрашиваются и не хранятся; бот не хранит
  тексты сообщений. Токены сессий хранятся в базе только как SHA-256. Гость получает случайный
  идентификатор; при входе через MAX его прогресс объединяется с профилем `max:<id>`.
- **Резервные копии:** `docker compose --profile tools run --rm backup` (PostgreSQL →
  `backups/*.dump`), `… run --rm media-backup` (файлы), восстановление –
  `BACKUP_FILE=<файл> docker compose --profile tools run --rm restore`.

Схема таблиц, ключи прогресса, правила контента, календарь и 152-ФЗ – [docs/DATA.md](docs/DATA.md).

### API

Автоматически (нужен только Node.js ≥ 22, зависимости не нужны):

```bash
API_BASE_URL=http://localhost:3000 TEST_API_PASSWORD=olympus-local-test node scripts/api-smoke.mjs
# или, если установлены зависимости: pnpm test:api
```

13 шагов: health → login → запрос без токена даёт `401` → reset → каталог → тема (без ответов и
тестов) → урок → проверка задачи (ответ из `test-data.json` засчитан) → отметка олимпиады → старт
и сохранение пробника → завершение (все ответы из `test-data.json` дают полный балл) → профиль
(прогресс сохранён) → повтор и очистка. Итог: `Olympus API smoke test: OK`. Тот же скрипт
проверяет production: `API_BASE_URL=https://olympus-edu.ru TEST_API_PASSWORD=<пароль> node scripts/api-smoke.mjs`.

Вручную через `curl`:

```bash
BASE=http://localhost:3000
TEST_API_PASSWORD=olympus-local-test
TOKEN=$(curl -s -X POST $BASE/api/v1/auth/login -H 'Content-Type: application/json' \
  -d "{\"username\":\"test_user\",\"password\":\"$TEST_API_PASSWORD\"}" \
  | sed -E 's/.*"accessToken":"([0-9a-f]+)".*/\1/')
curl -s -X POST $BASE/api/v1/test/reset -H "Authorization: Bearer $TOKEN"
curl -s $BASE/api/v1/topics/math-4-01 -H "Authorization: Bearer $TOKEN"
curl -s -X POST $BASE/api/v1/tasks/math-4-01-task-1/check -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"answer":"26"}'
curl -s $BASE/api/v1/profile -H "Authorization: Bearer $TOKEN"
```

Полный сценарий со всеми ответами – [docs/API.md](docs/API.md#52-сценарий-проверки-через-curl).

## 14. Известные ограничения

- **Проверка программ зависит от внешнего Judge0 CE**, который не входит в compose. Без него
  задачи по программированию не проверяются (код сохраняется), в пробниках такие ответы – «Не
  проверено» до перепроверки.
- **Вход через MAX и чат-бот работают только с настоящим токеном бота** и приложением на
  публичном HTTPS-адресе. Локально – гостевой режим, бот в режиме `disabled`. Часть поведения
  клиентов MAX (диплинки `open_app` на iOS/Android, cookie в мобильном WebView, совпадение id
  пользователя в боте и мини-приложении) можно подтвердить только на устройствах – список в
  [docs/MAX-INTEGRATION.md](docs/MAX-INTEGRATION.md#6-что-нужно-проверить-с-настоящим-токеном-и-на-устройствах).
- **Напоминания бота выключены** (`BOT_REMINDERS=off`): правила MAX (п. 1.5) допускают сервисные
  сообщения только по договору с MAX. Функция реализована и включается переменной после
  согласования.
- **Календарь обновляется вручную** редактором (раз в неделю осенью, реже зимой и летом); интеграции
  с системами организаторов нет. «Я участвую» – отметка для ребёнка, а не регистрация у
  организатора. Даты могут меняться – у каждой записи указаны источник и дата проверки.
- **Гостевой прогресс привязан к браузеру** (cookie на год); в профиль MAX он переносится, только
  если вход через MAX произошёл в той же сессии.
- **Один общий пароль учителя**, без личных учётных записей и журнала «кто что правил» (история
  версий сохраняет содержимое, но не автора).
- **Лимит попыток входа хранится в памяти** одного процесса `web`; при нескольких экземплярах нужен
  общий счётчик. Адрес клиента берётся из `X-Real-IP`, которому можно доверять только за Caddy.
- **Контент:** только 4–6 классы, математика и информатика; задач на доказательство (`proof`) в
  контенте пока нет, хотя приложение их поддерживает; эталонные решения задач на программирование
  написаны на Python (ребёнок может решать на любом из 6 языков).
- **Медиафайлы** хранятся в локальной эмуляции R2 на том же сервере; автодеплой делает резервную
  копию только PostgreSQL.
- **Реквизиты оператора** в разделе «О приложении» – заглушки «[заполнить: …]»; удаление данных по
  запросу выполняется вручную ([docs/DATA.md](docs/DATA.md#8-персональные-данные)).

## 15. Порядок остановки и повторного запуска решения

```bash
docker compose stop              # остановить, контейнеры сохраняются
docker compose start             # запустить снова

docker compose down              # остановить и удалить контейнеры; данные (volumes) сохраняются
docker compose up -d             # запустить снова
docker compose up -d --build     # запустить с пересборкой после изменения кода

docker compose logs -f web       # логи (web, bot, runner, postgres)
docker compose ps                # состояние и healthcheck
```

**Не используйте `docker compose down -v`, если данные нужны:** флаг `-v` удаляет volumes с
PostgreSQL и файлами. Это же – способ полностью сбросить локальный стенд: после `down -v`
команда `up -d` создаст базу заново и загрузит контент.

Перед рискованными действиями сделайте копию: `docker compose --profile tools run --rm backup`
(восстановление – [docs/DATA.md](docs/DATA.md#7-резервные-копии-и-восстановление)). На сервере
те же команды выполняются с `-f compose.production.yaml`.
